WebGUI UX 提案总览

WebGUI 有两个视图、共用一套界面:Review 审阅 Agent 起草的压缩方案,Selection 由用户自己圈定压缩范围。下面先看每个视图的问题与提案方向,再进入对应页面查看可交互原型。

① Review — 审阅 /midcompact:review-webui

用户任务:判断“这份草案能不能 commit”。

现状问题

  • 看不到被压缩的原文,无法核对摘要忠实性
  • 看不到压缩后的结果,只能脑补 commit 效果
  • 没有汇总决策数字;空 summary 的坑要到终端 commit 才撞上

提案要点

  • 决策条:ranges / 覆盖 / −chars% / pending 一行看全
  • Timeline 加 Raw ⇄ Projected 切换,直视 commit 后的上下文
  • 点 atom 弹原文抽屉(新增 GET /api/atom/:ref)
  • pending 前置到列表、投影卡、关闭对话框
  • reviewed 清单 + 吸底操作行 + “回终端 commit”指引
  • 锚点条 → now → after commit 估算投影条(与 Selection 共用组件)
现状(对照) 查看提案 →

② Selection — 圈选 /midcompact:select-webui

用户任务:选出要压缩的 atom,存成草案。

现状问题

  • 核心操作纯鼠标,大 session 圈选很慢
  • Add / Keep / 不选 三态模型,但 KEEP 与“不选”投影上等价,徒增心智负担
  • 右栏文案是系统语言(“normalized, non-overlapping ranges… DraftPlan”)

提案要点

  • 合并为两态:选中=压缩,未选=保留(KEEP 由“不选”天然表达)
  • 键盘圈选:↑↓ 移光标,Space 选中,G 整组切换
  • 左侧实时显示“将生成哪些 range”,右侧实时汇总
  • 顶部细汇总内嵌 “if committed now” 估算投影条,随圈选实时变化
现状(对照) 查看提案 →

③ 全局改动(体现在两个提案页)

  • 会话已在终端关闭 → 页面顶部横幅 + 只读(提案页有“模拟”按钮)
  • 浅色/深色主题保留,微标签对比度提到 WCAG AA
  • 文案去系统腔:DraftPlan → draft/plan,删“provider usage fact”类免责句
  • 契约修订:允许“展示级”token 估算(标注 est. + 不确定带 + 假设说明),事实 chars 并行保留

④ 明确不做(契约约束)

  • 浏览器里不放 commit 按钮 — 人工门禁留在终端
  • 估算仅止于展示,无否决权 — commit 门禁永远基于事实(pending/边界/受保护);数字错误只会“看着不准”,不会导致错误提交
  • 不做 remove 撤销 — 需要新增服务端契约,收益不匹配

阅读说明:顶部深色条与总览页是原型导航/解说层(中文);进入子页后,浅色区域是 App 界面(英文,对应产品观感)。“提案”页的交互可操作,“现状”页仅作对照示意。勾选右上角“变更标注”会在提案页显示编号说明。
